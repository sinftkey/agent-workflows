## 8. Git 工作流

- 新分支使用 `<Agent 工具名/角色/身份>/` 前缀，**角色（开发 / 审核 / 测试）在任务开始前明确**，后续操作以该角色为准；
- **角色权限分离**：开发写生产代码（自验测试即写即测即删，不提交）；审核只提意见、绝不提交代码；测试只提交测试文件。完整权限矩阵与标准流程编排见 `<协作工作流文档>` 第 2、3 节；
- 提交前必须通过：格式化、静态检查、测试、构建；
- 提交信息使用 Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` / `test:` / `chore:`）；
- 命令级操作与回退见 `<Git 工作流文档>`；
- 多人 / 多 Agent 协作规则见 `<协作工作流文档>`；
- 不提交与任务无关的改动；工作区已有未提交改动时，先确认归属再动手。
